### **评测维度：不看 PPT，只看疗效**

我从 5 个维度打分，每个维度 10 分，满分 50。

|  |  |
| --- | --- |
| 🚀 上手体验 | 从注册到第一个 Agent 跑通要多久 |
| 🧠 核心能力 | 工具调用、记忆、多 Agent 协作、RAG |
| 💰 定价模型 | 免费额度、按量计费、企业版价格 |
| 🔌 生态集成 | 插件数量、API 对接、部署方式 |
| 🏭 落地案例 | 有没有真实的商业化落地案例 |

### **1. Coze（扣子）—— 字节跳动出品，「抖音级」产品力**

#### **上手体验：⭐⭐⭐⭐⭐（9/10）**

**Coze 是我测过的所有平台里，上手最快的。没有之一。**

从注册到搭建一个能用的客服 Agent，**全程不到 15 分钟**。

它的交互设计明显继承了字节系产品的基因——每个功能都有引导，每个步骤都有模板，你甚至不需要知道什么是 prompt engineering，拖拖拽拽就能搭出一个像模像样的 Agent。

![Image 2: Coze 搭建流程](https://developer.qcloudimg.com/http-save/yehe-2775261/95a4f23344d84a2739c8114df2cdf4be.png)

Coze 搭建流程

#### **核心能力：⭐⭐⭐⭐（7.5/10）**

**优势：**

*   **插件市场**：800+ 官方和社区插件，覆盖搜索、天气、股票、翻译、图片生成等
*   **工作流编排**：可视化拖拽，支持条件分支、循环、并行
*   **多模态支持**：语音、图片、视频理解 能力都不错
*   **Bot Store**：做好的 Agent 可以一键发布到豆包、飞书、微信、网页

**短板：**

*   **多 Agent 协作能力弱**：目前只支持单 Agent 工作流，没有多 Agent 编排
*   **私有化部署不支持**：数据必须过字节的云，政企客户会有顾虑
*   **底层模型选择有限**：主力是豆包大模型，第三方模型接入不够灵活

#### **定价：⭐⭐⭐⭐⭐（9/10）**

**免费额度非常慷慨。** 个人用户每天有 500 次 API 调用，对于原型验证和小规模部署完全够用。企业版按量计费，价格在国内平台里属于中等偏低。

#### **生态集成：⭐⭐⭐⭐（8/10）**

发布渠道丰富（豆包 App、飞书、微信公众号、网页嵌入、API），但**只能部署在字节云上**，没有私有化选项。

#### **落地案例：⭐⭐⭐⭐（7/10）**

Coze 的案例以中小企业和个人开发者为主。电商客服、内容创作、知识问答等轻量级场景表现不错，但**大型企业的标杆案例较少**。

> **总分：40.5 / 50****适用场景：** 快速验证、内容创作、轻量级客服、个人效率工具

### **2. Dify —— 开源界的一面旗帜**

#### **上手体验：⭐⭐⭐⭐（8/10）**

Dify 有两种用法：云端版和私有化部署。

云端版体验和 Coze 接近，注册即用，**20 分钟搭建第一个 Agent**。

私有化部署用 Docker Compose 一键拉起，**技术团队半天内可以跑通**：

![Image 3: Dify 私有化部署](https://developer.qcloudimg.com/http-save/yehe-2775261/8612aec3dcb15cfbf8f3bff9fc7a6ce6.png)

Dify 私有化部署

#### **核心能力：⭐⭐⭐⭐⭐（9/10）**

**Dify 的核心能力是最全面的，这也是它在开发者圈子里口碑最好的原因。**

*   **RAG 引擎**：内置向量检索 + 全文检索混合模式，支持多种分段策略
*   **Agent 编排**：支持 ReAct、Function Call、Multi-Agent 多种模式
*   **模型灵活性**：接入 20+ 模型供应商（OpenAI、Claude、通义千问、DeepSeek、本地 Ollama）
*   **工作流引擎**：可视化 DAG 编排，支持条件/循环/并行/人工审核节点
*   **API 优先**：每个应用自动生成 REST API，方便集成到现有系统

**短板：**

*   **企业级功能需付费**：SSO、审计日志、权限管理等在企业版
*   **社区版性能上限**：大规模并发需要自己优化部署架构

#### **定价：⭐⭐⭐⭐（8/10）**

**社区版完全免费开源**，这是 Dify 的杀手锏。云端版有免费额度（200 次/天），Pro 版 59 美元/月，Team 版 159 美元/月。私有化部署社区版免费，企业版需要商业授权。

#### **生态集成：⭐⭐⭐⭐⭐（9/10）**

GitHub**50k+ Stars**，社区活跃度在同类项目中遥遥领先。有丰富的第三方插件和模板，API 文档完善，和各种前端框架（Next.js、Flutter）有现成的集成方案。

#### **落地案例：⭐⭐⭐⭐⭐（9/10）**

这是 Dify 的强项。由于支持私有化部署，**大量中大型企业在用 Dify 搭建内部知识库和业务 Agent**。金融、制造、医疗、教育行业都有标杆案例。

> **总分：43 / 50****适用场景：** 企业级 Agent 开发、私有化部署、知识库、复杂业务流程

### **3. 阿里百炼 —— 阿里云全家桶的 AI 延伸**

#### **上手体验：⭐⭐⭐⭐（7/10）**

如果你是阿里云老用户，百炼的上手体验是流畅的——因为账号、计费、资源都打通了。

但如果你是新用户，**阿里云的控制台复杂度本身就是一道门槛**。找到百炼入口、理解"模型服务"和"智能体"的关系、搞清楚 RAM 权限——这些对新手不太友好。

#### **核心能力：⭐⭐⭐⭐（8/10）**

*   **通义千问全系列模型**：Qwen-Max、Qwen-Plus、Qwen-Turbo，以及视觉、音频模型
*   **智能体工厂**：预制了大量行业模板（电商客服、法务审核、代码助手）
*   **RAG 能力**：对接阿里云 OpenSearch、Elasticsearch、AnalyticDB
*   **MCP 协议支持**：最近加入了 Model Context Protocol 支持

**短板：**

*   **绑定阿里云生态**：你的数据、计算、存储全在阿里云上，迁移成本高
*   **开放性不足**：对非阿里系模型的支持不如 Dify

#### **定价：⭐⭐⭐（7/10）**

有免费试用额度，但**商用阶段按 Token 计费，价格中等**。优势是如果你本来就在用阿里云，不需要额外的基础设施投入。

#### **生态集成：⭐⭐⭐⭐（7.5/10）**

和阿里云产品（OSS、RDS、SLS、函数计算）深度集成，钉钉一键发布。但**和非阿里系产品的集成需要自己开发**。

#### **落地案例：⭐⭐⭐⭐（8/10）**

阿里系电商场景是强项：**淘宝客服智能体、1688 供应商助手、盒马选品分析**等都是百炼驱动的。政务和金融领域也有不少案例。

> **总分：37.5 / 50****适用场景：** 阿里云深度用户、电商场景、钉钉生态

### **4. 百度千帆 —— 中文理解的"一哥"**

#### **上手体验：⭐⭐⭐（7/10）**

千帆平台功能很全，但**信息密度太高**。首页塞满了"大模型平台"、"知识库"、"Agent Builder"、"AppBuilder"、"ModelBuilder"——

你分不清 AgentBuilder 和 AppBuilder 有什么区别？放心，我也分了半天。

**简单来说：AppBuilder 适合零代码用户，AgentBuilder 适合开发者。**

#### **核心能力：⭐⭐⭐⭐（8/10）**

*   **文心大模型全系列**：ERNIE 4.5、ERNIE 4.5 Turbo、ERNIE Speed
*   **中文语义理解**：这是百度的看家本领，在中文 NLP 任务上表现确实强
*   **知识库管理**：支持结构化/非[结构化数据](https://developer.cloud.tencent.com/techpedia/1570?from_column=20065&from=20065)，有专门的知识图谱能力
*   **组件丰富**：预制了 60+ 工具组件（天气查询、地图导航、百度搜索、文档解析等）

**短板：**

*   **产品线过多，定位不清**：新用户容易在多个产品之间迷路
*   **海外模型接入困难**：接入 OpenAI / Claude 等海外模型的体验不如 Dify

#### **定价：⭐⭐⭐（7/10）**

免费额度有限。ERNIE 4.5 按 Token 计费，价格在国内属于中等。企业版需要单独商务对接。

#### **生态集成：⭐⭐⭐⭐（7/10）**

和百度搜索、百度地图、百度网盘等自家产品深度集成。但**对外部生态的开放性中等**，API 文档质量参差不齐。

#### **落地案例：⭐⭐⭐⭐（8/10）**

政务和金融是千帆的强势领域。**多家国有银行、政务大厅、央企**在用千帆做智能问答和流程自动化。中文知识密集型场景是它的主场。

> **总分：37 / 50****适用场景：** 国企/政务、中文知识管理、百度生态用户

### **5. Microsoft Copilot Studio —— 微软生态的"胶水"**

#### **上手体验：⭐⭐⭐⭐（7.5/10）**

如果你的公司用 Microsoft 365 全家桶——Teams、Outlook、SharePoint、Power Platform——那 Copilot Studio 的上手体验非常丝滑。

**它不是一个独立的产品，而是微软生态的"AI 胶水层"。**

![Image 4: Copilot Studio 流程](https://developer.qcloudimg.com/http-save/yehe-2775261/e3b049292169b8b42fd8ceadb3d591b5.png)

Copilot Studio 流程

#### **核心能力：⭐⭐⭐⭐（7.5/10）**

*   **深度集成 Microsoft Graph**：直接读取邮件、日历、文档、Teams 消息
*   **Power Automate 联动**：触发自动化流程，审批、通知、数据同步
*   **多语言 Agent**：内置 40+ 语言支持，适合跨国企业
*   **Azure OpenAI 驱动**：GPT-4o、GPT-4.5 作为底层模型

**短板：**

*   **离开微软生态就失去灵魂**：如果你不用 Microsoft 365，这个产品对你没意义
*   **定价昂贵**：企业级功能的价格门槛高
*   **国内可用性**：需要 Azure 中国区，部分功能受限

#### **定价：⭐⭐（5/10）**

**Copilot Studio 的定价是最贵的。** 每个 Agent 每月 200 美元（约 1400 元），还不包含底层模型调用费。对中小企业来说门槛偏高。

#### **生态集成：⭐⭐⭐⭐⭐（9/10）**

如果你在微软生态里，集成体验是天花板。Teams Bot、Outlook 插件、SharePoint 知识库、Power BI 数据分析——一键打通。

#### **落地案例：⭐⭐⭐⭐（8/10）**

**外企和跨国公司是主力用户。** 全球 500 强中大量企业在用 Copilot Studio 做内部知识问答、HR 自助服务、IT Helpdesk。国内案例相对较少。

> **总分：37 / 50****适用场景：** 外企、Microsoft 365 深度用户、跨国企业

### **6. LangGraph —— 开发者的"终极武器"**

#### **上手体验：⭐⭐（5/10）**

**LangGraph 不是给普通用户用的。**

没有可视化界面，没有拖拽编排，没有一键部署。它是一个 Python 框架——

你需要写代码。

![Image 5: LangGraph 代码示例](https://developer.qcloudimg.com/http-save/yehe-2775261/c647e825938fcd53378abd07f2982bf6.png)

LangGraph 代码示例

如果你是开发者，这可能反而是优势——没有任何低代码平台的"框架限制"，你拥有完全的自由度。

#### **核心能力：⭐⭐⭐⭐⭐（10/10）**

**LangGraph 的核心能力是所有平台中最强的，没有之一。**

*   **状态图（StateGraph）**：用有向图定义 Agent 的状态转移，支持任意复杂的控制流
*   **多 Agent 编排**：真正的多 Agent 协作——supervisor、hierarchical、swarm 模式
*   **人在回路**：任意节点插入人工审核，支持中断/恢复
*   **持久化**：内置 checkpoint 机制，Agent 可以跨会话保持状态
*   **流式输出**：逐 Token 流式返回，支持中间步骤可视化
*   **模型无关**：任何 LLM 都能接入

**短板：**

*   **学习曲线陡峭**：需要理解图论、状态机、异步编程
*   **没有现成的****UI**：前端展示需要自己开发（或用 LangSmith）
*   **部署自己搞**：没有托管服务，需要自建基础设施

#### **定价：⭐⭐⭐⭐⭐（10/10）**

**完全开源免费。** MIT License，无任何商业限制。你只需要付底层模型的 API 费用。

#### **生态集成：⭐⭐⭐⭐（8/10）**

LangChain 生态的一部分，和 LangSmith（监控）、LangServe（部署）配合使用。社区活跃，GitHub **30k+ Stars**。

#### **落地案例：⭐⭐⭐⭐（7/10）**

落地案例以技术公司为主。很多 AI 创业公司的底层 Agent 框架就是 LangGraph。但由于门槛高，**传统企业的案例较少**。

> **总分：40 / 50****适用场景：** 复杂 Agent 编排、AI 创业公司、技术团队自研

### **选型决策树：3 个问题帮你选**

别纠结了。回答三个问题，答案就出来了：

**Q1：你有没有技术团队？**

*   没有 → **Coze**（零代码，15 分钟上线）
*   有，但不想自己维护基础设施 → **Dify 云端版** 或 **百炼/千帆**
*   有，而且想完全掌控 → **Dify 私有化** 或 **LangGraph**

**Q2：你的数据能不能上****公有云****？**

*   可以 → 随便选
*   不行，必须私有化 → **Dify**（唯一开源可私有化的成熟选项）

**Q3：你在哪个云/生态上？**

*   阿里云 → **百炼**
*   百度云 → **千帆**
*   Microsoft 365 → **Copilot Studio**
*   不绑定任何厂商 → **Dify** 或 **LangGraph**

### **我的看法：Agent 平台的终局**

说几个判断：

**1. 低代码平台会赢在"量"，代码框架会赢在"质"**

80% 的 Agent 需求是"简单场景 + 快速上线"——客服、问答、内容生成。这些场景，Coze 和 Dify 已经够用了。

但剩下 20% 的"复杂编排 + 深度定制"需求，只有 LangGraph 这种代码框架能搞定。

**2. 私有化部署是企业的刚需**

不管宣传多好，大中型企业——尤其是金融、医疗、政务——**数据不能出门**。这意味着不支持私有化的平台，天花板是中小客户。

Dify 在这个赛道上占据了绝对优势。

**3. 最终的赢家是"不绑定生态"的平台**

百炼绑阿里云，千帆绑百度云，Copilot Studio 绑微软——这些都是"只要你在我的生态里就很爽，离开就很痛"的模式。

但企业不会永远待在一个云上。**模型在迭代，最好的模型每三个月换一次。** 能灵活切换模型和基础设施的平台，长期看才有竞争力。
